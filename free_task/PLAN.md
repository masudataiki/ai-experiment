# 自由課題 計画書（PLAN.md）

ノイズを足すデータ拡張の強さと、壊れ方ごとのトレードオフ

最終更新: 2026-11-12

---

## 1. 目的（問い）

- **問い1（追試）**: 論文（Yin et al. 2019 など）で報告されたトレードオフが、day3 の小さな CNN でも起きるか。
  - 報告されている内容: ガウスノイズを足すデータ拡張で学習すると、ノイズ・ぼかしには強くなり、霧・コントラスト低下には弱くなる。
- **問い2（独自）**: ノイズ拡張の強さ σ を変えると、得と損はどう変わるか。ちょうどいい σ はあるか。
  - 論文は CIFAR-10 で σ = 0.1 に固定していて、強さを変える実験はしていない。
- **予想**: σ が大きいほどノイズには強くなる。そのかわり、霧・コントラスト低下への弱さと、元画像（壊れていない画像）での誤り率の悪化も大きくなる。

## 2. 学習データ

| 項目 | 決定内容 |
|---|---|
| データセット | 本物の CIFAR-10（`torchvision.datasets.CIFAR10`、`download=True` で VM に取得） |
| 学習用 50,000 枚の分け方 | 学習 45,000 枚 ＋ 検証 5,000 枚（`random_split`、分け方は seed 0 で固定） |
| テスト用 10,000 枚 | 「元画像」の評価に使う（学習・モデル選択には使わない） |
| 画素値の範囲 | **0〜1 のまま（`ToTensor()` のみ、平均・標準偏差による正規化はしない）** |

- 正規化しない理由: ノイズの強さ σ を「0〜1 の画素値に対する標準偏差」として決める。CIFAR-10-C の画像（0〜255 の整数）も 255 で割って同じ範囲にそろえる。こうすると、学習と評価で値の意味が一致する。
- day3 の `MyCifarDataset`（mini_cifar 用）は使わない。

| 項目 | 決定内容 |
|---|---|

| ドロップアウト | なし（`dropout = 0`）。比べる条件をノイズの強さだけにするため |
| 最適化 | Adam、学習率 0.001（day3 の `--optimizer adam`） |
| バッチサイズ | 100（day3 の既定値） |

| モデルの選び方 | 検証精度が最大のエポックのモデルを使う（検証データは 5,000 枚あるので、day3 の 150 枚より安定する） |

- 検証データにはノイズを足さない（壊れていない画像で選ぶ）。

## 4. 学習時に入れるノイズ（比較する実験の一覧）

### 4.1 全モデル共通の拡張

左右反転 ＋ 切り抜き（day3 の `--augment` と同じ。`RandomHorizontalFlip()` と `RandomCrop(32, padding=4)`）。論文も全実験でこれを使っている。

### 4.2 ノイズ拡張の中身

- 変換の順番: 反転・切り抜き → `ToTensor()`（0〜1 にする） → ノイズを足す → 0〜1 に収める（`clamp`）
- ノイズの強さ: 画素ごとに、平均 0・標準偏差 s の正規分布の乱数を足す。
- s の選び方: 毎回 0〜σ の一様分布からランダムに選ぶ（論文と同じ考え方）。
- 論文との違い: 論文はバッチごとに s を選ぶ。本実験は `transform` の中で実装するので、画像ごとに s を選ぶ。この違いは README に書く。
- 学習中、画像は毎エポック `__getitem__` で読み直され、そのたびに `transform` が実行される。だから毎エポック違うノイズが乗る。

### 4.3 実験の一覧

| ID | ノイズの最大強さ σ | 内容 | 出力フォルダ | 優先度 |
|---|---|---|---|---|
| M0 | 0 | ノイズ拡張なし（比較の基準） | `result/noise_s000` | 必須 |
| M1 | 0.05 | 弱いノイズ | `result/noise_s005` | 必須 |
| M2 | 0.1 | 論文と同じ強さ | `result/noise_s010` | 必須 |
| M3 | 0.2 | 強いノイズ | `result/noise_s020` | 必須 |
| M4 | 0.3 | とても強いノイズ | `result/noise_s030` | 必須 |
| M5 | 0.1 ＋ ぼかし | ノイズとぼかしを混ぜた拡張（トレードオフを和らげられるか） | `result/noise_blur_s010` | 任意（時間が余ったら） |

- M5 のぼかしの強さと、ノイズとぼかしの混ぜ方: **未定**
- 乱数の種を変えた繰り返し（seed 1, 2）: **未定**。時間が余れば M0 と M2 だけ繰り返し、「乱数による結果のばらつき」と「σ による差」を比べる。day3 では、同じ条件でも環境の違いで 2 ポイント程度ずれた。

## 5. 評価

### 5.1 使うデータ

| 壊れ方 | ファイル | 強さ | 予想（σ を上げたとき） | 役割 |
|---|---|---|---|---|
| 元画像 | CIFAR-10 テスト 10,000 枚 | – | 少し悪化 | 壊れていない画像での損 |
| ガウスノイズ | `gaussian_noise.npy` | 1〜5 | 良くなる | 強くなるはずのもの |
| ガウスぼかし | `gaussian_blur.npy` | 1〜5 | 良くなる | 強くなるはずのもの |
| 霧 | `fog.npy` | 1〜5 | 悪くなる | 弱くなるはずのもの |
| コントラスト低下 | `contrast.npy` | 1〜5 | 悪くなる | 弱くなるはずのもの |
| 明るさ | `brightness.npy` | 1〜5 | わからない | 対照 |
| （正解ラベル） | `labels.npy` | – | – | 全ファイル共通 |

- CIFAR-10-C の形式: 各 `.npy` は 50,000 × 32 × 32 × 3（uint8）。1〜10,000 枚目が強さ 1、…、40,001〜50,000 枚目が強さ 5。
- ぼかしに `defocus_blur.npy` も加えるか: **未定**（論文の図に合わせるなら候補）。

### 5.2 測る値

- **誤り率**（＝ 1 − 正解率、%）を、各モデル × 各壊れ方 × 各強さ（1〜5）ごとに測る。
- 壊れ方ごとに強さ 1〜5 の平均を出す。これを各モデルの代表値にする。
- **M0 との差**（ポイント）を出す。マイナスなら良くなった、プラスなら悪くなった。
- 記録: 評価スクリプトの出力を CSV（`result/eval_<ID>.csv`）に保存し、スプレッドシートの「結果」シートに転記する。

### 5.3 発表に使う図

1. ヒートマップ: 縦にモデル（σ）、横に壊れ方、マスの値は M0 との差 → 問い1
2. 折れ線グラフ: 横軸 σ、縦軸誤り率、壊れ方ごとに 1 本 → 問い2
3. 1 行の波形: テスト画像 1 枚の横 1 行の明るさを、元画像・ノイズ・ぼかし・霧・コントラスト低下で並べる → 周波数の直感的な説明

## 6. データの準備（VM）

```bash
# 0. 共有 VM なので、使う前に GPU とディスクの空きを確認
nvidia-smi
df -h ~

# 1. CIFAR-10-C を取得（約 2.9 GB の tar）
mkdir -p ~/data && cd ~/data
wget -O CIFAR-10-C.tar "https://zenodo.org/records/2535967/files/CIFAR-10-C.tar?download=1"

# 2. 使うファイルだけ取り出す（全部展開しない）
tar -xf CIFAR-10-C.tar \
  CIFAR-10-C/gaussian_noise.npy CIFAR-10-C/gaussian_blur.npy \
  CIFAR-10-C/fog.npy CIFAR-10-C/contrast.npy CIFAR-10-C/brightness.npy \
  CIFAR-10-C/labels.npy

# 3. 中身を確認できたら tar は削除してディスクを空ける
ls -lh CIFAR-10-C/
rm CIFAR-10-C.tar
```

- 取り出した 6 ファイルで約 0.8 GB（1 ファイル約 150 MB）の見込み。
- 本物の CIFAR-10（約 170 MB）は、学習スクリプトの初回実行時に `torchvision` が `~/data/cifar10` に自動でダウンロードする。
- `data/` と `result/` はサイズが大きいので `.gitignore` に入れ、GitHub には上げない。データの取り方は README に書く。
- データの置き場所（`~/data` か、リポジトリ内の `data/` か）: **未定**
